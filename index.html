NSANet-Outage-Simulator

NSANet-Outage-Simulator Explanation: The ClassiNet Outage Simulator, developed by Randy Singh of Kalsnet Consulting Group, is a training and analysis application that simulates outages on a large, segmented, high security enterprise network modeled loosely on a classified environment, using only fictional data or incident files that users upload themselves. It models a network of ten invented sites, including a core headquarters, two data centers, two encryption gateways that each protect a secure enclave, and three remote sites. It generates a realistic incident history across eight common outage types: fiber cuts, routing instability, DNS and directory failures, encryption gateway key expiry, certificate expiry, power and cooling failures, misconfiguration errors, and traffic congestion. For every incident it calculates time to detect, time to restore, outage duration, user minutes lost, site availability against a service level target, mean time between failures, error budget consumed, estimated cost, and a weighted severity score that blends users affected, duration, packet loss, and site criticality. A topology and what if simulator lets users fail any site or link, then runs a graph search to show which sites are cut off from the core, how many users are affected, and how backup links would change the result. It also ranks single points of failure, shows synthetic latency, packet loss and utilization trends, explains each outage case with a cause to fix diagram and a response playbook, and exports results as PDF, Word, text, and CSV reports. The application is written in Python and built with Streamlit for the web interface, Pandas and NumPy for data processing, Plotly and Matplotlib for charts, NetworkX for network graph analysis, Graphviz for diagrams, python docx for Word reports, and ReportLab for PDF reports. In practice it helps network operations teams and managers train staff on outage response without touching sensitive systems. It finds weak points in a network design before they cause real outages, makes the business case for redundancy and better monitoring with clear numbers, shows which root causes to fix first, and turns raw incident logs into professional reports for briefings and service level reviews.
